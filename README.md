# AgriVerse

AgriVerse is a production-oriented field intelligence application for farmers,
field agents, and agronomists. It combines deterministic soil, crop, and weather
logic with cited image diagnosis, organization-isolated retrieval, and human
review.

The legacy CRA, Express, and Flask prototype is retained locally under
`recycle/legacy-prototype/` as recoverable migration history. It is excluded
from version control; the supported runtime is the new monorepo.

## Architecture

| Path | Purpose |
|---|---|
| `apps/web` | Next.js 15 farmer dashboard, scan flow, agent chat, and staff review console |
| `apps/api` | FastAPI REST API, ARQ worker, SQLAlchemy models, and Alembic migrations |
| `packages/api-client` | TypeScript types generated from the committed OpenAPI contract |
| `deploy` | OpenResty and systemd integration examples |
| `docs` | Production and centralized-infrastructure runbooks |

Runtime dependencies are Postgres 17 with pgvector, Redis, a private
S3-compatible MinIO bucket, direct OpenAI APIs with optional Gemini fallback,
and Open-Meteo weather data. Supply secrets through `.env` or the process
environment; no inference gateway or secret-management service is required.

## Implemented capabilities

- Organization-scoped farms and fields with PostgreSQL row-level security.
- Phone/PIN farmer enrollment using single-use invitations, E.164 normalization,
  Argon2 PIN hashing, progressive lockout, short access tokens, and rotating
  refresh sessions.
- Keycloak, Google, and Microsoft staff OIDC with email-bound invitations and one-time
  exchange codes.
- Versioned deterministic fertility scoring, rice/wheat/tomato suitability, and
  weather alerts.
- Direct encrypted MinIO uploads, strict image validation/re-encoding, SHA-256
  duplicate reuse, asynchronous diagnosis, citation controls, feedback, and an
  agronomist confirmation queue.
- Separate OpenAI/Gemini retrieval vectors, pgvector HNSW indexes, region/tier filtering,
  reranking, confirmed-case retrieval, and licensed-document ingestion.
- Field-authorized agronomist chat with soil, weather, scan, and document
  context; multilingual answer configuration; prompt-injection screening.
- Usage records, immutable mutation/AI audit events, quotas, rate limits,
  idempotency records, privacy export/erasure, PWA shell, secure headers, and
  generated OpenAPI types.

## Local development

Requirements:

- Node.js 22 and Corepack
- pnpm 10.14
- Python 3.12–3.14
- uv
- Postgres with pgvector, Redis, and MinIO

Create configuration:

```bash
cp .env.example .env
```

In PowerShell, use `Copy-Item .env.example .env` when creating the file for the
first time. The API and the web `dev`, `build`, and `start` scripts read the root
`.env`; existing shell variables take precedence. The API also permits a local
`.env` in its working directory to override the root file.

Install and migrate:

```bash
corepack pnpm install --frozen-lockfile
uv sync --project apps/api --frozen
uv run --directory apps/api alembic upgrade head
```

On Windows, stop the API and ARQ worker before running `uv sync` (Ctrl+C in
their terminals). Running Python processes can lock loaded `.pyd` files and
cause `Access is denied` during package updates or removal. A successful Alembic
command does not validate an interrupted dependency sync. If package metadata
is already incomplete, stop those processes and recreate only `apps/api/.venv`
from the frozen lockfile; keep `.env` and database data intact.

Generate application secrets from the repository root before starting services.
This single-line command works in PowerShell and generates two independent
values using Python's cryptographically secure `secrets` module:

```powershell
uv run --project apps/api python -c "import secrets; print('JWT_SECRET=' + secrets.token_urlsafe(48)); print('OAUTH_SESSION_SECRET=' + secrets.token_urlsafe(48))"
```

Copy the two generated lines into root `.env`, replacing the placeholder values.

| Variable | Purpose |
|---|---|
| `JWT_SECRET` | Signs application access and refresh tokens |
| `OAUTH_SESSION_SECRET` | Signs the session cookie used during Keycloak/OIDC login |
| `FIELD_DATA_ENCRYPTION_KEY` | Currently unused; leave blank. Setting it does not enable field-level encryption |

Keep the generated values private, out of version control, and stable across
restarts. Restart the API and worker after changing them. Rotating `JWT_SECRET`
invalidates existing application tokens, so users must sign in again.

Weather uses Open-Meteo with the following root `.env` setting:

```dotenv
OPEN_METEO_BASE_URL=https://api.open-meteo.com/v1
```

The application appends `/forecast` and the field's coordinates, requests current
conditions and a three-day hourly forecast, and caches results for ten minutes.
Heat, rain, and wind alerts are generated by AgriVerse's own threshold rules.

Run each of the following commands from the repository root in a separate
terminal, and leave all three terminals running.

Terminal 1 - API:

```powershell
uv run --project apps/api uvicorn agriverse.main:app --app-dir apps/api --reload --reload-dir apps/api/agriverse --port 8000
```

Terminal 2 - background scan worker:

```powershell
uv run --project apps/api arq agriverse.workers.WorkerSettings
```

Terminal 3 - web application:

```powershell
corepack pnpm --filter @agriverse/web dev
```

The web app runs at `http://localhost:3001`; API documentation is available at
`http://localhost:8000/docs` outside production. Langfuse is accessed at
`https://wisdom-dev.local/langfuse/`. To change the application port, update `WEB_PORT`, `WEB_ORIGIN`,
`CORS_ORIGINS`, and `WEB_OAUTH_CALLBACK_URL` together in `.env`. A shell `PORT`
or explicit `--port` argument overrides `WEB_PORT`. If the selected port is
occupied, startup fails instead of silently switching to a different origin.

### Local startup troubleshooting

- **Repeated reloads mention `.venv.before-repair-*` or other dependencies:**
  use the API command above with `--reload-dir apps/api/agriverse`. This watches
  application source only, so changes in archived virtual environments do not
  restart the API. Stop the old API with Ctrl+C before using the updated command.
- **`localhost:3001` shows `ERR_CONNECTION_REFUSED`:** start the web application
  in Terminal 3 and wait for Next.js to print `Ready`. The API and ARQ worker
  do not serve the frontend.
- **`EADDRINUSE: address already in use :::3001`:** another process already owns
  port 3001. First open `http://localhost:3001/login`. If AgriVerse loads, use the
  running instance; starting another copy produces this error. To restart it,
  press Ctrl+C in the terminal running the existing web server, then run the
  Terminal 3 command again.
- **`/docs` returns HTTP 200 but the page is blank:** Swagger UI needs its
  JavaScript and CSS from `cdn.jsdelivr.net` plus its inline initializer. The
  API gives `/docs` a dedicated Content Security Policy with a per-response
  script nonce and permission for those CDN assets. After updating the API,
  restart it if reload is disabled and refresh the page. If it remains blank,
  check the browser console/network panel for blocked or failed asset requests
  and confirm the CDN is reachable. API documentation is disabled in production.
- **Image PUT returns `405` with `XMinioPaidTierLicenseRequired`:** the request
  reaches MinIO, but its current license rejects AES256 server-side encryption.
  For local development with MinIO Free, set `S3_SERVER_SIDE_ENCRYPTION=none`
  in root `.env` with `APP_ENV=development`. This stores original uploads and
  processed images without server-side encryption at rest. Restart the API and
  worker, then retry the upload to obtain a fresh signed URL. AES256 remains the
  default; staging and production reject `none` and require storage configured
  to support encrypted writes. The scan UI displays this license error explicitly.

If the terminal owning port 3001 is unavailable, identify the listener in
PowerShell before stopping anything:

```powershell
$webListener = Get-NetTCPConnection -State Listen -LocalPort 3001
$webListener | Select-Object LocalAddress, LocalPort, OwningProcess
$webListener.OwningProcess | Sort-Object -Unique | ForEach-Object {
  Get-CimInstance Win32_Process -Filter "ProcessId = $_" |
    Select-Object ProcessId, Name, CommandLine
}
```

After confirming the process belongs to the AgriVerse web server, stop that
specific PID with `Stop-Process -Id <OwningProcess>` (replace the placeholder
with the displayed number), then restart the web application. If it belongs to
another application, resolve that application's port use or change the
AgriVerse port and related `.env` origins together as described above.

The optional Langfuse configuration uses
`LANGFUSE_HOST=https://wisdom-dev.local/langfuse/`, including the `/langfuse/`
prefix. Setting the host and both project keys enables direct LLM traces for
generation and embeddings. Traces include provider, model, task, timing, status,
and available token counts; prompts, images, answers, credentials, and field
content are excluded. Langfuse is independent of the optional OTel collector.
Leaving the host or either key empty disables its exporter.

Python HTTPS clients use the operating system's trusted CA roots, including the
Windows certificate store. Set `TLS_CA_BUNDLE` to an additional organization CA
PEM file when needed. Certificate and hostname verification remain enabled.

Use a restricted `DATABASE_URL` for application traffic. An optional separate
`MIGRATION_DATABASE_URL` supplies Alembic's DDL connection; if omitted, migrations
use `DATABASE_URL`. Keep migration credentials out of production runtime service
environments. The opt-in administrative script
`apps/api/scripts/provision_runtime_role.py` provisions a new `agriverse_runtime`
role and saves generated credentials privately to root `.env`. It refuses to
reset an existing role's password.

On the local wisdom deployment, `/minio/` is the management console. The S3 API
route in `deploy/openresty/agriverse-minio-api.inc` exposes only the application
bucket, so use `S3_PUBLIC_ENDPOINT_URL=https://wisdom-dev.local` and keep
`S3_ENDPOINT_URL=http://localhost:9000`. This preserves signed bucket/object paths.
`S3_SERVER_SIDE_ENCRYPTION=AES256` is the default for both browser uploads and
worker image writes. The current AIStor Free setup accepts local test uploads
with `S3_SERVER_SIDE_ENCRYPTION=none` and `APP_ENV=development`; these objects
are stored without server-side encryption at rest. This setting keeps the same
MinIO endpoints, bucket, and credentials. It does not change bucket permissions
or HTTPS certificate verification. `none` is allowed only in development/test.
Staging and production require an AES256-capable storage configuration.

OpenTelemetry export is optional: leave `OTEL_EXPORTER_OTLP_ENDPOINT` empty to
disable it, or set it to your collector's HTTP endpoint to enable it. Optional
telemetry setup failures are logged without preventing API startup. Restart the
API after changing these settings. OIDC is optional in every environment,
including production. Staff/admin accounts with a registered phone and PIN can
sign in with `STAFF_PIN_LOGIN_ENABLED=true` (the default). Set it to `false` to
disable staff PIN login and use a configured OIDC provider instead. Keep the
same value in the API and web environments, and restart both after changing it.

Bootstrap is allowed only on an empty database. Set these values in root `.env`:

```dotenv
BOOTSTRAP_NAME="Demo cooperative"
BOOTSTRAP_PHONE="+919876543210"
BOOTSTRAP_PIN="123456"
BOOTSTRAP_EMAIL="admin@example.com"
```

The phone number is the login ID; the password is a 6-12 digit PIN. Keep PINs
quoted to preserve leading zeroes and choose your own value. The name identifies
the organization. Email is optional for PIN login and must match the
OIDC identity used for staff login, including Keycloak in development.

Run this single-line command in PowerShell or Bash:

```text
uv run --project apps/api python -m agriverse.cli bootstrap
```

CLI options `--name`, `--phone`, `--pin`, and `--email` can override the environment
values. Missing credentials fail before connecting to the database. Only the PIN
hash is stored; credentials are not printed. Bootstrap prints the generated
organization ID and a sign-in link. When `STAFF_PIN_LOGIN_ENABLED=true`, that link
selects the **Sign in as staff/admin with PIN** option in development and
production. Use the phone and PIN from `.env` to sign in. Keycloak, Google, and
Microsoft OIDC remain optional alternatives. OIDC-only accounts need a registered
phone and PIN before they can use PIN login; this setting does not create
credentials or change existing accounts.

Changing bootstrap variables after initialization does not reset an existing
account. Bootstrap never overwrites an existing organization.

For direct AI keys, provider fallback, migrating existing retrieval vectors, and
creating your development Keycloak client, follow
[AI and Keycloak setup](docs/AI_AND_KEYCLOAK_SETUP.md). The dedicated
[Keycloak setup guide](docs/KEYCLOAK_SETUP.md) covers client creation, users,
discovery, environment settings, and troubleshooting. OIDC buttons appear only
after the corresponding provider is configured.

## Security notes

Never commit `.env` files, access keys, OAuth secrets, AI provider keys, or
database credentials. Production startup rejects weak JWT/OAuth session
secrets. Use a non-superuser Postgres runtime identity without `BYPASSRLS`, keep
MinIO buckets private, and expose only OpenResty publicly.
